# Реальные измерения → симуляция → проверка улучшения

## Что реализовано

`scripts/gradient_retention.py` — исследовательская модель удерживания в градиенте.
Она подбирает параметры LSS `log10(kw)` и `S` по реальным временам удерживания
при разных программах, а затем рассчитывает удерживание при заданной программе.
TFV и FTC калибруются отдельно. Выбранный градиент `report:0386` сохранён
в `gradient_campaign_template.json` вместе с исходной программой и её SHA-256.
Программа не подбиралась повторно. Наличие выбранного градиента само по себе
не задаёт параметры взаимодействия вещества с колонкой.

Численные проверки используют только искусственные тестовые данные.
Они проверяют код, не подтверждают точность для TFV/FTC. Параметры для этих
двух веществ не выдуманы; новых прогнозов для заказчика пока нет.

## Физический смысл и границы

Используется `log10(k) = log10(kw) − S × phi`, где phi — объёмная доля органики,
а не обязательно доля канала B. Для выбранного метода B — чистый метанол
с добавкой, поэтому используем B/100. Поддерживается постоянный поток и температура,
один органический модификатор, фиксированные рецептуры фаз и согласованный pH.
Модель предполагает разбавленный образец, мгновенное равновесие и отсутствие
дисперсии/адсорбции растворителя. Для ионизируемых TFV/FTC зависимость LSS может
оказаться недостаточной даже при фиксированном pH водной фазы.

Решается интегральное уравнение движения в скорректированном времени:

`integral(0 .. tr − t0 − extra) [1 / k(phi(t − dwell))] dt = t0`.

Это учитывает распространение градиента, а не подставляет состав на входе
в изократическую формулу. Начальный состав действует до прихода градиента.
Расчёт не продолжает программу бесконечно: если вещество не вышло в заданное
окно регистрации, возвращается `not_eluted_within_program`, без выдуманного tR.

Требуются измеренные величины с источником:

- `t0_column_min`: время прохождения неудерживаемого вещества внутри колонки;
- `dwell_time_min`: эффективная задержка градиента до входа в колонку;
- `extra_column_time_min`: только послеколоночная задержка до детектора;
- `time_reference: sample_entry_at_column_inlet`: начало времени согласовано
  с входом образца в колонку. Если есть перенос от инжектора до колонки,
  его нужно учитывать при согласовании времён программы и измерений.

Число `column.t0` из RepoRT автоматически не используется. Значение 0 для
задержек тоже требует обоснования. Для выбранного метода эти поля пока пустые.
Ширины, формы, площади пиков, Rs и давление этот модуль не предсказывает.

Основание для интегральной модели:
[Espinosa et al., Approaches to model the retention and peak profile in linear gradient reversed-phase liquid chromatography](https://www.sciencedirect.com/science/article/pii/S0021967313001830).

## Как калибровать

1. Сделать копию шаблона для каждой точной молекулы; заполнить её полный InChIKey.
2. Подтвердить параметры прибора, фаз и времён. Все записи относятся к одной
   физической системе и одной рецептуре. Изменение pH или колонки требует другой калибровки.
3. Добавить в `observations` реальные измерения: ID, источник, программу
   (`time_min`, `phi`), измеренное `tr_min`, `label_origin: experiment`, `reviewed: true`.
4. Заранее выбрать разные программы для `split: calibration` и `split: validation`.
   Повторы одной программы не становятся независимыми условиями.
5. Требуются минимум три разных обучающих программы. Это технический порог,
   а не гарантия достаточности данных. Неинформативные программы могут не позволить
   определить параметры; модуль проверяет обусловленность задачи и попадание на границы.

```bash
.venv/bin/python scripts/gradient_retention.py fit \
  --input reviewed_tfv_campaign.json \
  --out reports/physical_retention/tfv_model_v1.json

.venv/bin/python scripts/gradient_retention.py simulate \
  --input reports/physical_retention/tfv_model_v1.json \
  --program requested_program.json \
  --out reports/physical_retention/tfv_simulation_v1.json
```

Выходные файлы создаются без перезаписи. Используйте новую версию после новых
измерений. Проверочные времена не участвуют в подгонке. Расчёт MAE не означает
успешную валидацию: нужно оценивать число случаев, ошибки, невышедшие пики,
порядок TFV/FTC и допустимые для задачи пределы. Неизвестные программы помечаются
`new_program_unvalidated`, даже если диапазон составов выглядит знакомым.

## Как симуляции смогут улучшать CatBoost

Гипотезу нужно проверить отдельным экспериментом с одинаковыми реальными
проверочными данными для трёх вариантов:

1. CatBoost на реальных данных.
2. Физическая модель, откалиброванная только на обучающей части реальных данных.
3. CatBoost с дополнительной физической информацией: например прогнозом
   симулятора как признаком или ограниченным набором синтетических обучающих строк.

При разделении данных по приборам/методам все симуляции наследуют принадлежность
своих калибровочных измерений. Нельзя калибровать симулятор на отложенных измерениях,
а затем обучать на полученных из них синтетических строках. Для варианта с прогнозом
как признаком нужны предсказания вне обучающей группы, иначе возникнет утечка.

Вес синтетических строк и выбор варианта настраиваются на отдельной выборке выбора;
финальная проверка остаётся только на нетронутых реальных измерениях. Добавление
тысяч симуляций не увеличивает число независимых экспериментальных наблюдений.
Улучшение признаётся только при снижении ошибки на реальных данных без ухудшения
целевой пары, порядка выхода и оценки неопределённости.

Этот сравнительный эксперимент пока **не выполнен**: нет реальной калибровочной
серии для текущей пары. Автоматическое дообучение отключено. Выход симулятора
помечен `label_origin: simulation`, `training_ready: false`, содержит SHA-256 модели
и не принимается загрузчиком экспериментальных данных или лабораторным журналом.
В перспективе для синтетики нужен отдельный явный исследовательский путь обучения.

Повторные расчёты CatBoost не заменяют реальные прогоны. Полезный цикл:
**реальный опыт → калибровка → виртуальные варианты → выбор следующего опыта →
новое измерение → сравнение ошибки**.
